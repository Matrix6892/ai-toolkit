# План улучшения архитектуры

## Когда применять

Существующий проект трудно понимать, менять или проверять; сначала нужен обоснованный план перехода. Этот вариант просит только документы, не изменение рабочего кода.

## Что передать

Доступ к проекту, один важный сценарий и конкретную трудность, если известна. Нужна локальная копия ai-toolkit; недоступные файлы агент должен назвать.

## Ожидаемый результат

Проверенная против кода спецификация целевого поведения и поэтапный план, по которому исполнитель может действовать без переизобретения общих контрактов.

## Как достигается результат

Агент прослеживает сценарий по коду, связывает предложение с местом, последствием и проверкой, затем разбивает переход на законченные части.

## Текст для копирования

```text
Подготовь план улучшения архитектуры существующего проекта, чтобы следующие изменения было проще понимать, реализовывать и проверять.

Прочитай действующие инструкции проекта и Skills/product-engineering/SKILL.md в локальной копии ai-toolkit. Открой руководства по архитектуре и проверке; состояние, интеграции и окружение — по затронутым гарантиям.

Проследи важный пользовательский сценарий по коду, зависимостям и тестам. Для каждой существенной рекомендации укажи место, конкретную проблему или гипотезу, последствие, минимальное изменение и способ проверки пользы. Сохрани удачные границы; соглашения чужого стека не навязывай.

Запиши в существующую документацию проекта спецификацию целевого поведения и поэтапный план. Если подходящего места нет, используй docs/architecture.md и docs/architecture-plan.md. Для каждого этапа опиши обязанности и контракты, владельцев состояния, сохраняемое поведение, реальные примеры/ошибки, область изменений, зависимости и проверяемую готовность. Команды бери из фактического проекта.

Сверь документы с кодом и ссылками, назови неизвестное и способ его выяснить. Сейчас нужны только спецификация и план; реализацию по ним начнём отдельным поручением.
```
