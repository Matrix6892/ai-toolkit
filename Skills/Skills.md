# Скиллы

Last reviewed: 2026-10-14.

Скилл — повторяемая инструкция, которую агент читает под подходящую задачу. Например, при запуске продукта она помогает перевести идею в поведение, понятную часть реализации и доказательство результата. Само клонирование библиотеки не включает скилл в приложение.

При создании или обновлении пакета прочитайте [гайд по созданию скиллов](Создание%20скиллов.md): режим вызова обязательно задаётся явно в формате целевой среды.

## Выбор по задаче

| Задача | Пакет | Результат и статус |
|---|---|---|
| Смутная жалоба, заранее выбранное средство или конфликт целей; подготовка/приёмка разрешённого поручения; сверка и выполнение поручения исполнителем | [Огранка: три режима](ogranka/SKILL.md) | Один вход: 1. Пользователь ↔ LLM; 2. LLM ↔ LLM — 2.1 координатор, 2.2 исполнитель. Результат: случай и проверяемый шаг; бриф и приёмка; исполнение со свидетельствами. **draft**, статическая и содержательная самопроверка 2026-10-14; независимого эксперимента и проверки модельной маршрутизации нет |
| Новый продукт или архитектурное изменение | [product-engineering](product-engineering/SKILL.md) | Сценарий, контракт, реализация и проверка; подробности ниже |

«Огранка» выбирает ветку по текущей роли и задаче, без обязательного вопроса при понятном контексте: пользователь ↔ LLM, `TO ORCHESTRATOR` или `TO WORKER`. Обычно читается один reference; при запросе обоих текстов допустимы две ветки. `tools.md` нужен только при конкретном пробеле, происхождение — только при проверке пакета. Для известной небольшой правки достаточно прямой работы и проверки.

`product-engineering` ведёт продуктовую и архитектурную реализацию; при необходимости «Огранка» помогает прояснить проблему или поручение. Обязательной цепочки пакетов нет. Прежний `intent-based-delegation` стал [обычным указателем совместимости](intent-based-delegation/README.md), без активного пакета. [Карта смыслов, самопроверка, статическая матрица маршрутов и прежние пробы](ogranka/references/source-and-changes.md) отделяют новую редакцию от ранее проверявшихся текстов; их результаты не доказывают работу нового маршрутизатора.

## Использование на другой машине

Обновите локальную копию ai-toolkit по [README](../README.md). Попросите агента прочитать `Skills/product-engineering/SKILL.md`, применить его к задаче и читать только нужные ссылки. Для постоянного обнаружения установите всю папку `product-engineering`, включая `references/`, в поддерживаемое место скиллов вашей среды, сохранив существующие файлы. Здесь установка не выполнялась.

Пакет самостоятельный: внутренние ссылки остаются внутри папки скилла. Дополнительные инструменты, подписки или Scalens для использования не обязательны. Делегирование и запуск внешних систем выполняются только в рамках текущего поручения и правил среды.

Единый пакет `ogranka` оформлен для Codex: в `agents/openai.yaml` явно задано `policy.allow_implicit_invocation: true`. Для установки в Claude Code перенесите режим вызова по [существующему гайду форматов](Создание%20скиллов.md), не добавляя поле Claude в исходный Codex-пакет. Другой агент может читать пакет как инструкцию без установки. Рабочие ссылки «Огранки» остаются внутри пакета; запись о происхождении ссылается на общую выборку, которая не нужна для применения.
