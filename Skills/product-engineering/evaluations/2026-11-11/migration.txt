Реализуй migrate.py на стандартной библиотеке Python, CLI: python3 migrate.py --source SOURCE --target TARGET. Это изолированный перенос локальных SQLite-копий, не действие в рабочем продукте. SOURCE должен остаться неизменным, существующий TARGET всегда сохраняется без перезаписи.

В SOURCE таблицы:
orders(id TEXT PRIMARY KEY, status TEXT, address TEXT, revision INTEGER NOT NULL)
history(order_id TEXT, seq INTEGER, event TEXT, PRIMARY KEY(order_id, seq))

В TARGET сохраняются эти таблицы, все ID, address, revision и полная история без изменения текста. Только status преобразуется: created -> new, pickup_ready -> ready_for_dispatch, delivered -> completed. Ни одно другое значение статуса не разрешено угадывать или пропускать. ID должен быть непустой строкой; revision неотрицателен. Каждый history.order_id должен ссылаться на существующий orders.id, seq положителен; история сохраняет свои номера и события. Текст может быть Unicode и содержать переводы строки.

Перенос читает согласованный снимок двух таблиц: SOURCE может получать другие записи во время чтения. При любой некорректности — ненулевой exit code, понятная причина, SOURCE не меняется, TARGET не появляется даже частично. При успехе — пригодный для чтения TARGET с проверенными данными. Временные файлы принадлежат этому запуску и убираются, чужие пути не удаляются. Повтор с уже существующим TARGET должен отказать, сохранив его. Пути файлов могут содержать пробелы и нелатинские символы.

Добавь и выполни собственные тесты на временных копиях внутри своей рабочей папки. Результат: migrate.py и короткий report.md с проверенными сценариями и нерешёнными ограничениями. Настройка серверов и скачивание зависимостей не нужны.
