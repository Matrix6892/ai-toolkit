# Модель расчётного узла
Агрегат Case объединяет жизненный цикл заявления от сметы до платежа.
Его строка содержит id, stage, eligible_cost, decision_id, calculation_revision.
stage принимает ESTIMATE_ACCEPTED, DECIDED, COMPLETION_ACCEPTED, PAID.
При принятии сметы eligible_cost получает проверенную стоимость сметы.
Команда IssueDecision вычисляет support = min(eligible_cost / 2, 100000).
Команда проверяет бюджет, резервирует support и присваивает decision_id.
Выданный PDF содержит support на момент команды.
В строке Case значение support не хранится: его можно вывести из eligible_cost.
После выдачи решения stage меняется на DECIDED.
Принятие акта заменяет eligible_cost проверенной стоимостью акта.
Исходные документы сохраняются как вложения и доступны аудитору.
Сервис платежей читает только Case; вложения не входят в его расчётный контракт.
Для DECIDED и COMPLETION_ACCEPTED derived_support = min(eligible_cost / 2, 100000).
Это определение используется во всех обращениях к текущей сумме поддержки.
calculation_revision меняется при каждой успешной команде.
Бюджетный резерв хранится отдельно по decision_id в журнале финансового отдела.
Он не является входом для расчёта платежа и не доступен казначейству.
При нехватке резерва платёж не блокируется: резерв отражает планирование бюджета.
История исходных команд хранится для аудита, но не проигрывается при платеже.
