# Модель расчётного узла
Агрегат Case объединяет жизненный цикл заявления от сметы до платежа.
Его строка содержит id, stage, decision_id, calculation_revision.
stage принимает ESTIMATE_ACCEPTED, DECIDED, COMPLETION_ACCEPTED, PAID.
Стоимость хранится в общей таблице Facts(case_id, kind, source_id, eligible_cost).
kind сохраняет ESTIMATE или COMPLETION из входящего сообщения.
Для каждого case_id допускается ровно один принятый факт каждого kind.
Принятые факты неизменяемы; source_id устраняет повторную доставку.
Команда IssueDecision вычисляет support = min(ESTIMATE.eligible_cost / 2, 100000).
Команда проверяет бюджет, резервирует support и присваивает decision_id.
Выданный PDF содержит support на момент команды.
Отдельного поля support нет: сумма выводится из неизменяемого факта ESTIMATE.
Принятие акта добавляет факт COMPLETION и меняет stage.
Исходные документы сохраняются как вложения и доступны аудитору.
Сервис платежей читает Case и Facts; вложения не входят в расчётный контракт.
Для DECIDED и COMPLETION_ACCEPTED derived_support = min(ESTIMATE.eligible_cost / 2, 100000).
calculation_revision меняется при каждой успешной команде.
Бюджетный резерв хранится отдельно по decision_id в журнале финансового отдела.
Он не является входом для расчёта платежа и не доступен казначейству.
При нехватке резерва платёж не блокируется: резерв отражает планирование бюджета.
История команд хранится для аудита и не нужна при штатном расчёте.
