# Контракт выплаты
Владелец расчёта — сервис фонда, владелец отправки — адаптер казначейства.
CalculatePayment допускается только при stage = COMPLETION_ACCEPTED.
Половины рублей округляются вниз при каждом делении.
Алгоритм читает COMPLETION.eligible_cost и derived_support из Case и Facts.
payment_amount = min(COMPLETION.eligible_cost / 2, derived_support).
Команда сохраняет результат в payment_outbox с decision_id и payment_id.
Отправка в казначейство меняет stage на PAID после подтверждения.
Повтор команды с тем же payment_id возвращает уже сохранённый результат.
Новый payment_id для PAID отклоняется.
Для PDF решения используется вычисленная при IssueDecision сумма support.
В бухгалтерский журнал уходит ровно payment_amount из outbox.
Ни адаптер, ни журнал не добавляют проверок суммы из архивного решения.
Отрицательные суммы и акты без решения отклоняются до расчёта.
События в рамках одного case_id обрабатываются последовательно.
Поддерживается один принятый акт на заявление.
Принятие повторного source_id не добавляет факт и не меняет его стоимость.
В договоре с казначейством гарантирована доставка без изменения суммы.
Отправленный платёж не корректируется другим фоновым процессом.
Проверка выданного решения человеком перед обычной выплатой не требуется.
